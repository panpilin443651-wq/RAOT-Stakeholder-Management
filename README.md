# RAOT Stakeholder Management

ระบบสารสนเทศเพื่อการจัดการผู้มีส่วนได้ส่วนเสียของ **การยางแห่งประเทศไทย (กยท.)**
พัฒนาตามโครงสร้างเมนู รหัสฟอร์ม และ flow การทำงานของระบบ BAAC Stakeholder Management
(อ้างอิงเอกสาร `EP5_Stakeholder Engagement Strategy_ธ.ก.ส..pdf` หน้า 26–37)

## เริ่มใช้งาน

```bash
npm install
npm run db:seed     # สร้างฐานข้อมูลพร้อมข้อมูลตั้งต้น (data/raot-sm.db)
npm run dev         # เปิด http://localhost:3001
```

> `npm run db:seed` จะ **ลบฐานข้อมูลเดิมทิ้งแล้วสร้างใหม่** ทุกครั้ง

## ปีงบประมาณ

ปีงบประมาณของ กยท. เริ่มเดือน **ตุลาคม** (ปี 2568 = ต.ค. 2567 – ก.ย. 2568)
ตั้งค่าเดือนเริ่มต้นได้ที่ `FISCAL_YEAR_START_MONTH` ใน [lib/fiscal.ts](lib/fiscal.ts) จุดเดียว

ผู้ดูแลระบบเพิ่มปีงบประมาณใหม่ได้เองที่เมนู **ตั้งค่าระบบ → ปีงบประมาณ** (`/settings/fiscal-years`)
โดยไม่ต้องรัน `npm run db:seed` ใหม่ ปีที่เพิ่มจะขึ้นในช่องเลือกปีของทุกหน้าจอทันที

**ปีปัจจุบันใช้ร่วมกันทั้งระบบ** — ปีที่ผู้ดูแลระบบตั้งเป็น "ปีปัจจุบัน" คือค่าตั้งต้นของ
**ทุกหน้าจอของผู้ใช้ทุกคน** เปลี่ยนที่เดียวแล้วมีผลกับทุกคนทันที

**ผู้ใช้ทุกสิทธิ์เลือกดูปีย้อนหลังได้** — ทุกหน้ามีช่องเลือกปีงบประมาณ (ปีปัจจุบันมีป้ายกำกับไว้)
เลือกแล้วข้อมูล ตัวเลข และแผนภูมิในหน้านั้นเปลี่ยนตามปีที่เลือก
ขอบเขตตามส่วนงานยังบังคับใช้เหมือนเดิม — ผู้บันทึกข้อมูลดูย้อนหลังได้เฉพาะของส่วนงานตัวเอง
และปุ่ม "บันทึกใหม่" จะพาปีที่กำลังดูอยู่ไปตั้งเป็นค่าตั้งต้นในฟอร์มด้วย

| ทำอะไรได้ | เงื่อนไข |
| --- | --- |
| เพิ่มปีงบประมาณ | ปี พ.ศ. ระหว่าง 2500–2700 และต้องไม่ซ้ำกับปีที่มีอยู่ |
| ตั้งเป็นปีปัจจุบัน | มีได้ปีเดียว — เป็นปีที่ทุกหน้าจอเลือกให้อัตโนมัติเมื่อเปิดหน้า |
| ลบปีงบประมาณ | เฉพาะปีที่ **ยังไม่มีข้อมูลผูกอยู่** และ **ไม่ใช่ปีปัจจุบัน** |

เมนูนี้และ API ทั้งหมด (`/api/fiscal-years`) จำกัดสิทธิ์ไว้ที่ **ผู้ดูแลระบบ (ADMIN)** เท่านั้น
เพราะปีงบประมาณเป็นข้อมูลหลักที่ทุกส่วนงานใช้ร่วมกัน

## องค์ความรู้ (Knowledge Management)

เดิมเป็นบทความตายตัว 4 หัวข้อ `[600]`–`[603]` ที่แก้ได้เฉพาะในโค้ด ตอนนี้เป็นทะเบียนที่เพิ่มหัวข้อได้เอง

- **`/km`** — หน้ารายการ มี **ช่องค้นหา** (ค้นจากชื่อหัวข้อ คำโปรย หมวดหมู่ และเนื้อหา) และตัวกรองหมวดหมู่
  รายการเรียงตาม **วันที่บันทึกข้อมูล** ใหม่สุดขึ้นก่อน
- **`/km/<id>`** — หน้าอ่าน แสดงเนื้อหาแบบ Markdown พร้อมวันที่บันทึกและวันที่แก้ไขล่าสุด
- ผู้ดูแลระบบเห็นปุ่ม **+ เพิ่มหัวข้อองค์ความรู้** ในหน้ารายการ และปุ่ม **แก้ไข / ลบ** ในหน้าอ่าน
  ผู้ใช้อื่นอ่านได้อย่างเดียว

หมวดหมู่พิมพ์ขึ้นใหม่ได้เอง หรือเลือกจากหมวดที่มีอยู่แล้ว (ช่องกรอกมี autocomplete)
เนื้อหารองรับ Markdown เท่าที่ [components/Markdown.tsx](components/Markdown.tsx) แสดงผลได้ — หัวข้อ ย่อหน้า รายการ ตาราง blockquote

ฟอร์ม `[604]` บันทึกความต้องการความคาดหวัง ย้ายไปที่ `/expectations` (ยังอยู่ใต้เมนูเดิม)
